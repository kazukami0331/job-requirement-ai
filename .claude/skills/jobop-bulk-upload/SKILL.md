# ジョブオプ 求人一括アップロード用ファイルの作り方

ジョブオプの求人一括編集は、**求人案件一覧からダウンロードしたxlsxを編集して投げ返す**方式。
一見ただのExcelだが、**普通にxlsxを書き出すと必ず失敗する**。

## 最重要：セルは「共有文字列」でなければ読まれない

xlsxには文字列の持ち方が2つある。

- **共有文字列** … `xl/sharedStrings.xml` に実体を置き、セルは `<c t="s"><v>123</v></c>` と番号で参照
- **インライン文字列** … `<c t="inlineStr"><is><t>値</t></is></c>` とセル内に直接書く

**ジョブオプの取り込みは共有文字列しか読まない。** インライン文字列のセルは「空」として扱われる。

ややこしいのは、**ジョブオプ自身の書き出しがデータ列をインライン文字列で出してくる**こと
（見出し行だけは共有文字列）。だから書き出しをそのままコピーして行を足すと、足した行が丸ごと
空と見なされ、必須チェックで弾かれる。

実際に出たエラーと原因の対応：

| エラー | 原因 |
|---|---|
| `ファイルエラー（シート<DATA>にヘッダー・データがありません）` | 見出し行まで含め全セルがインライン文字列だった（openpyxl等で新規ブックを作ると `sharedStrings.xml` 自体が生成されない） |
| `採用ホームページIDが設定されていません。`（値は入っているのに） | データ行のセルがインライン文字列だった。最初の必須項目でつまずいて、そこだけ報告される |

**書き込む・複製する行は、全セルを共有文字列に変換すること。** これが唯一かつ決定的な要点。

## 作り方

同梱の `scripts/jobop_edit.py` がこの処理を実装している。まずこれを読んで、案件に合わせて使う。
自分でゼロから書き直さない。

### 1. 最新の書き出しを必ずもらう

ジョブオプ ＞ 求人管理 ＞ 求人案件一覧 ＞「ファイルダウンロード」。
**手元の古い書き出しを使い回さない。** 新しく作った求人ぶん求人案件IDが増えるし、公開状態も応募数も動く。
数日前のファイルだと対象IDが存在せず詰む。

### 2. 新規ブックを作らず、zipを開いて書き換える

`xl/worksheets/<dataシート>.xml` と `xl/sharedStrings.xml` だけを差し替え、
残り（styles.xml / MASTER・SHOPシート / printerSettings 等）は元のまま持ち越す。

openpyxl・pandas・xlsxwriter で新規ブックを作って保存する方法は使わない。

### 3. 既存行は消さず、末尾に足す

公式マニュアル（求人案件の一括編集方法）は「追加する行の求人内容を入力し保存します」で、
サンプル画像もダウンロードしたファイルに行を足した状態。既存行は全部 `操作コード 00`（スキップ）
なので残しても何も起きない。この形で成功実績がある。

### 4. 操作コードを正しく置く

`MASTER` シートに定義がある。

| 操作コード | 意味 |
|---|---|
| `00` | スキップ。書き出し時は全行これ |
| `01` | 登録（新規作成） |
| `02` | 更新（既存の求人案件IDを書き換える） |

- **新規登録**：`操作コード=01`、`求人案件ID=空白`。既存を複製するなら元の行をまるごとコピーし、
  店舗ID / 店舗名 / 管理コメント を差し替える
- **更新**：`操作コード=02` ＋ 対象の `求人案件ID`

### 5. 見出しの色が、その列を書いてよいかを示している

見出し行（2行目）のセルの塗りつぶしが列の区分になっている。

| 色 | 意味 |
|---|---|
| 黄 `FFFFA7` | 必須入力（14列。操作コード・採用ホームページID・店舗ID・職種コード・仕事内容１ など） |
| 無色 | 任意入力（183列。本文の大半はここ） |
| 灰 `C0C0C0` | **出力専用（56列）。書いても取り込まれない** |

灰色には `公開/非公開` `保存ステータス` `募集開始日` `募集終了日` `応募総数` `店舗名` `職種名` など、
**画面側やコードから自動で決まる項目**が入っている。コード列（黄）が正、名称列（灰）は表示用の写し。

実測：`公開/非公開=公開`、`募集開始日=2026/09/24` を入れて `01` で登録したが、
**取り込み後は非公開・募集開始日は空**だった。つまり一括アップロードで公開状態は作れない。

**公開は画面側の操作。** 求人案件一覧でチェックを入れて「公開」ボタン（一括選択可）。
アップロードで入った求人は必ず非公開から始まるので、渡すときにそう伝える。

`jobop_edit.py` は見出し色から `KIND` を作り、出力専用列に値を入れようとすると警告を出す。

### 6. 送る前に読み戻して検算する

- 同梱ファイル数・シート構成が元と同じか（`data` / `MASTER` / `SHOP`）
- **追加・変更した行に `inlineStr` が1つも残っていないか**
- 1行あたりのセル数と列の並びが元の行と完全一致しているか
- 本文（仕事内容・給与例など）が複製元と1文字も違わないか（**改行コードを含めて**）
- 操作コード・求人案件IDが意図どおりか（公開/非公開・募集開始日は出力専用なので検算しても意味がない）
- 既存行を1文字も変えていないか

## その他の落とし穴（全部実際に踏んだ）

### 見出しセルにフリガナが埋まっている

見出しの `操作コード` は共有文字列の中では `操作コードソウサ` として入っている（`<rPh>` にフリガナ）。
素朴に `<t>` を全部連結すると見出し名が変わり、**列の対応が静かにズレる**。
`操作コード` と `管理コメント` の書き換えが無言で失敗した原因がこれ。
`<si>`/`<is>` からテキストを取るときは `<rPh>` を無視する（`rich_text()` がその実装）。

### 空欄にするときセルを消してはいけない

元ファイルは空欄セルも `<c r="I5" s="7"/>` として必ず持っている（1行253セル固定）。
セル要素ごと削除すると1行の要素数が変わる。**セルは残して中身だけ消す。**

### 改行が消える

本文の改行はXML上で `&#xd;`（CR）＋ `&#xa;`（LF）。ElementTreeは `&#xd;` を生CRに展開してしまい、
そのまま書き出すと再読込でCRが失われる。**シリアライズ後に生CRを `&#xd;` に戻す。**

### dimension が嘘をついている

書き出しの `<dimension ref="A1:IT2"/>` は実際の行数と合っていない（240行あっても `2`）。
dimensionを信じる読み取り（SheetJS等）だと2行しか読めない。行を足したら実範囲に直す。

### 全セルが文字列

書式は全列 `numFmtId=49`（文字列）。IDらしきものも文字列で入っている。勝手に数値型にしない。

## エラーが出たときの調べ方

ジョブオプは**エラーファイルを返す**。これが一番の情報源。
`ファイル管理 ＞ アップロードファイル一覧` から落とせる。

- **txt** … ファイル全体のエラー
- **xlsx** … 行ごとのエラー。**元の253列＋末尾に1列（IT列）追加**され、そこにメッセージが入る。
  エラーになった行だけが返る

**まず、返ってきたエラーファイルと自分が送ったファイルを全列突き合わせる。**
差分が無ければ「値は正しく読めている＝バリデーションで弾かれている」と切り分けられる。

```python
for r in rows:
    for i in range(len(header)):
        if sent.cell(r,i+1).value != returned.cell(r,i+1).value:
            print(header[i], sent.cell(r,i+1).value, "->", returned.cell(r,i+1).value)
```

成功時は `ステータス=完了`、`件数（エラー件数）` が `3 (0)` のように出る。
アップロードした行数と件数が一致していれば正常。

## 影響範囲を必ず言葉で示す

求人の公開/非公開は募集の停止に直結する。ファイルを渡すときは、**何が起きて何が起きないか**を
毎回はっきり書く。

- `操作コード` の内訳（`01` が何行、`02` が何行、`00` が何行）
- `求人案件ID` が入っている行＝既存を書き換える行が何行か。**新規追加だけなら0行**
- 応募が入っている求人を止めるなら、その求人と応募件数
- **取り込み後は非公開で入ること**、公開は画面で一括選択→「公開」が要ること

「既存求人IDがファイルのどこにも出てこない」ことを全シート総当たりで確認できると、相手も安心して投げられる。

## いきなり全件流さない

1店舗・数行で試し、通ってから残りを流す。ただし**テストは本番と同じ経路にする**こと。
既存を `02` で更新するテストは、`01` の新規登録が通る保証にならない。本番が `01` ならテストも `01` で。
