# 数字の定義（採用モニタリング）

経営会議に出す数字なので、定義を固定する。ここに書いてある以外の数え方はしない。
**変更が必要になったときは、画面を変える前に必ず相談し、変更履歴に残す。**

最終更新: 2026-10-08 ／ 定義確定: 2026-10-08（カズヒコさん了承）

**確定した「採用」の定義**

> その期間（既定は今期＝9月1日以降）に**採用が決まった**人数のうち、
> **不足人数マスタに採用目標がある校舎**のもの。

今回の依頼の対象外である校舎（六本木オフィス・新宿校・京都本部・全国採用窓口など）は
目標を持たないため、応募も採用も数えない。全部を見たいときだけ、画面で「全校舎」に切り替える。

この定義のまま、不足人数マスタに校舎が足された場合は数字が動く（対象が増えるため）。
マスタを差し替えたときは、採用数と残り人数が変わることを前提に見る。

---

## 1. どこまでを数えるか（母数）

| 絞り込み | 既定 | 中身 |
| --- | --- | --- |
| 対象の校舎 | 不足人数マスタの校舎 | 不足人数マスタに採用目標が1名以上ある校舎だけ。六本木オフィス・全国採用窓口・京都本部など、採用目標を持たない拠点の応募と採用は入らない。「全校舎」に切り替えると全部入る |
| 集計期間 | **施策開始から（2026/07/23〜）** | 求人を出し直した日を起点にする。応募も採用も同じ起点で数える。開始日は画面で変更でき、ブラウザに記憶される。「今期（9月1日〜）」「全期間」にも切り替えられる |
| 雇用形態 | すべて | 業務委託・契約社員・正社員 |

**起点は1本。** 応募だけ9月から、採用は7月に応募した人も含む、という状態だと母数が揃わず、
採用率も予実も比べられない。応募・採用・面接のすべてを同じ起点で切る。

**期間をどの日付で切るか**は、数字ごとに違う。ここが混ざると数が合わなくなる。

- **応募**に関する数字 … 応募受付日
- **採用・面接**に関する数字 … 選考ステータス最終更新日（採用はそこで止まるので、更新日＝採用が決まった日）

**採用日についての注意。** ジョブオプのエクスポートに「採用日」の項目は無く、
選考ステータス最終更新日しか取れない。ジョブオプ上でまとめてステータスを更新すると、
実際にはもっと前に決まっていた人も、その更新日に採用が決まった扱いになる。
採用明細シートの「採用が決まった日」が特定の日に固まっていたら、それは一括更新の日。
週や月の採用数を見るときは、累計と合わせて見る。

校舎名は、不足人数マスタが「名古屋」、応募データが「名古屋駅前校」のように略されることがある。
店舗マスタの1校だけに前方一致する略称は同じ校舎として扱う。2校に当たるもの（「新宿」と「新宿本」）は別のままにする。

## 2. 上段のカード

| 数字 | 計算 |
| --- | --- |
| 直近週の応募 | 集計基準日を含む週（月〜日）に応募受付された件数。集計基準日は、取り込んだデータの最終更新時刻 |
| 前週差 | 直近週 − その前の週（確定済みの週） |
| 4週平均の応募 | 確定した直近4週の平均。集計途中の週は入れない（4日ぶんしかない週を1週として平均すると実態より低く出るため） |
| 選考中プール | いま「未対応・面接調整中・面接待ち・面接結果待ち」のいずれかにいる人数 |
| 面接待ち | 選考ステータスが「面接待ち」（面接日が確定済み）の人数 |
| **採用** | **この期間に採用が決まった人数**（ステータスが「採用」で、その更新日が期間内） |

---

## 3. 週次の応募数と採用数

- **青（応募）** … 応募受付日の週で数える
- **緑（採用）** … 採用が決まった週で数える。応募がいつかは問わない

同じ週の青と緑は別の人なので、対応しない。
緑の合計は、上の「採用」タイル、月次目標の「採用済み」と必ず同じ数字になる。

---

## 4. 選考ステータスの内訳・通過ファネル

**この期間に応募した人を追いかけた数**（コホート）。「どこで落ちているか」を見るためのもの。

ここに出る「採用」は、**その応募の中から採れた数**であって、上の「採用」タイルとは数え方が違う。
例：9月に応募した64件のうち採用3件（ファネル）／9月中に決まった採用18名（タイル）。
どちらも正しく、見ているものが違う。

## 5. 月次の目標と進捗

### 目標の作り方

1. **採用目標** = 不足人数マスタの校舎計（全校で58名）
2. **採用済み** = その期間に採用が決まった人数（校舎ごと）
3. **充足** = min(採用済み, 採用目標)。**残り** = 採用目標 − 充足
   - 目標3名の校舎に4名採れたら「4 / 3名（133%） 残り0名」。
   - 超過したぶんは他の校舎の不足を埋めないので、残りからは引かない。
   - そのため合計では「目標 − 採用済み」が残りと一致しないことがある。合計行に理由を出している。
4. **月ごとの採用目標** = 残りを按分期間（既定は当月〜マスタで一番遅い期限）に1名ずつ配る
5. **必要応募** = 残り ÷（応募→面接率 × 面接→採用率）を**校舎ごとに1回だけ切り上げ**
   - 既定は 30% × 60% なので、1名採るのに応募5.6件。
   - 校舎ごとに切り上げるので、単純な「残り × 5.6」より少し多くなる。
6. **月ごとの目標応募・目標面接** = 校舎の必要応募・必要面接を、採用目標を置いた月へ配る（月の合計は必ず校舎の数に戻る）

### 足し算の関係（ここが合っていれば整合している）

| 式 | 例 |
| --- | --- |
| 採用目標 ＝ 充足 ＋ 残り | 58 ＝ 27 ＋ 31 |
| 月ごとの採用目標の合計 ＝ **按分開始より前に充足した人数を引いた残り** | 58 − 14 ＝ 44 |
| 採用済み ＝ 充足 ＋ 目標超過 | 32 ＝ 27 ＋ 5 |
| 月ごとの採用実績（+Nを含む）の合計 ＝ 採用済み | 17（9月）＋ 15（10月）＝ 32 |
| 月ごとの採用実績（+Nを除く）の合計 ＝ 充足 | 14 ＋ 13 ＝ 27 |
| 月ごとの目標応募の合計 ＝ 必要応募 | 90 ＋ 66 ＋ 25 ＝ 181 |

**月ごとの採用目標を足しても採用目標（58名）にはならない。**
配っているのは「按分期間が始まる時点で残っていた人数」だけで、それより前に充足したぶんは配らない。
按分期間より前の月（9月など）は実績だけを出していて、目標は持たない。

**月ごとの目標は、期間が始まった時点で決めたまま動かさない。**
期間中に採れたぶんで目標を減らすと、その採用が「残りを減らす」と「その月の目標を埋める」の
両方に効いてしまい、10月に15名採れたのに10月の目標も15名のまま（＝達成扱い）になる。
いまの残り（58 − 充足）は上の合計行に出す。月の目標の合計といまの残りの差は、期間中に充足したぶん。

### 月ごとの目標が、月をまたぐと変わる場合がある

「按分する期間」を選ばずに既定のままにしていると、**開始月が当月に追随する**。
その結果、前の月に採りきれなかったぶんが、残りの月に上乗せされる（ローリング）。

| いつ見たか | 按分期間 | 10月 | 11月 | 12月 |
| --- | --- | --- | --- | --- |
| 10月 | 10〜12月 | 20 | 14 | 10 |
| 11月 | 11〜12月 | − | 30 | 13 |
| 12月 | 12月のみ | − | − | 43 |

**経営会議に出す計画を固定したいときは、「按分する期間」で 10月〜12月 を明示的に選ぶ。**
選んだ期間はブラウザに記憶され、月が変わっても割り直されない。
その場合、10月の目標20に対して実績が足りなければ、11月・12月の目標は増えずに「未達」として残る。

### 実績の数え方

| 行 | 実績 |
| --- | --- |
| 応募 | その月に応募受付された件数 |
| 面接 | その月に面接段階へ進んだ人数（ステータス最終更新日の月） |
| 採用 | その月に採用が決まった人数のうち、**充足に効いたぶん**（ステータス最終更新日の月） |

**採用の実績は「充足に効いた人数」で出す。**
目標3名の校舎で5名採れた場合、充足は3名で止まり、はみ出た2名は他の校舎の不足を埋めない。
これを月の進捗に乗せると「10月 15/20」のように、充足していないぶんで達成に見えてしまう。
はみ出たぶんは消さずに、実績の横へ `+2` と出す（進捗バーには含めない）。

採用が「充足に効いたぶん」かどうかは、校舎ごとに決まった順で判定する。
先に決まった人から目標の人数までが充足に効き、それ以降は超過になる。

9月など按分期間より前の月は「実績」列として、目標なしで実績だけ出す。

### 表に出ない応募

不足人数マスタに採用目標が無い校舎の応募は、表にも合計にも入らない。
何件あるか・どの校舎かを表の下に出している。マスタに載っているはずの校舎がそこに出ていたら、名前の書き方がマスタと違う。

## 6. これまでに定義を変えた履歴

同じ「採用」の数字が動いた理由。以後は勝手に変えない。

| 日付 | 変更 | 影響 |
| --- | --- | --- |
| 10/1 | 採用目標を持たない校舎（六本木オフィス等）を集計から除外 | 採用24 → 16 |
| 10/8 | 「名古屋」と「名古屋駅前校」が別校舎として扱われていたのを修正 | 採用 +2、応募 +10 |
| 10/8 | 目標を超えて採れた校舎の扱いを整理（充足は目標で頭打ち、超過は別表示） | 合計の引き算が合うようになった |
| 10/8 | 採用の数え方を「その期間に採用が決まった人」に統一（それまでは「その期間に応募した人のうち採れた数」と混在） | 採用タイル・週次グラフ・月次目標がすべて同じ数字になった |
| 10/8 | 集計の起点を施策開始日（7/23）に統一。応募が9月以降・採用が7月応募者ぶんも含む、という母数のずれを解消 | 応募の母数が増え、採用率が実態に合った |
| 10/8 | 目標を超えて採れたぶんを月の進捗から外し、`+N` で別に出す | 「10月15/20」のような、充足していないぶんでの達成表示が無くなった |
| 10/8 | 月ごとの目標を按分開始時点の残りから作るよう修正（期間中の採用で目標が縮む二重計上を解消） | 10月の目標が15→20に |
| 10/8 | 上の定義で確定（手集計35件との差は、目標を持たない校舎の採用と、起点日の違いによるものと確認） | 以後、数え方は変えない |
