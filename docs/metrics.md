# 数字の定義（採用モニタリング）

経営会議に出す数字なので、定義を固定する。ここに書いてある以外の数え方はしない。
**変更が必要になったときは、画面を変える前に必ず相談し、変更履歴に残す。**

最終更新: 2026-10-08 ／ 定義確定: 2026-10-08（カズヒコさん了承）

**確定した「採用」の定義**

> その期間（既定は今期＝9月1日以降）に**採用が決まった**人数のうち、
> **不足人数マスタに採用目標がある校舎、または六本木オフィス**のもの。

依頼の対象外である拠点（新宿校・京都本部・全国採用窓口など）は目標を持たないため、
応募も採用も数えない。全部を見たいときだけ、画面で「全校舎」に切り替える。

**六本木オフィスは目標が無くても数える**（2026-10-19 指示）。不足人数管理表は校舎の講師採用の
表なので本部・オフィスは載っていないが、実際に募集していて応募も来ているため。
採用目標は無いので、月次の目標と進捗（目標のある校舎だけの表）には出ない。

この定義のまま、不足人数マスタに校舎が足された場合は数字が動く（対象が増えるため）。
マスタを差し替えたときは、採用数と残り人数が変わることを前提に見る。

---

## 1. どこまでを数えるか（母数）

| 絞り込み | 既定 | 中身 |
| --- | --- | --- |
| 対象の校舎 | 不足人数マスタの校舎 ＋ 六本木オフィス | 不足人数マスタに採用目標が1名以上ある校舎と、六本木オフィス。全国採用窓口・京都本部・新宿校など、それ以外の目標を持たない拠点の応募と採用は入らない。「全校舎」に切り替えると全部入る |
| 集計期間 | **施策開始から（2026/07/23〜）** | 求人を出し直した日を起点にする。応募も採用も同じ起点で数える。開始日は画面で変更でき、ブラウザに記憶される。「今期（9月1日〜）」「全期間」にも切り替えられる |
| 雇用形態 | すべて | 業務委託・契約社員・正社員 |

**起点は1本。** 応募だけ9月から、採用は7月に応募した人も含む、という状態だと母数が揃わず、
採用率も予実も比べられない。応募・採用・面接のすべてを同じ起点で切る。

**期間をどの日付で切るか**は、数字ごとに違う。ここが混ざると数が合わなくなる。

- **応募**に関する数字 … 応募受付日
- **採用・面接**に関する数字 … 選考ステータス最終更新日（採用はそこで止まるので、更新日＝採用が決まった日）

**採用日についての注意。** ジョブオプのエクスポートに「採用日」の項目は無く、
選考ステータス最終更新日しか取れない。ジョブオプ上でまとめてステータスを更新すると、
実際にはもっと前に決まっていた人も、その更新日に採用が決まった扱いになる。
採用明細シートの「採用が決まった日」が特定の日に固まっていたら、それは一括更新の日。
週や月の採用数を見るときは、累計と合わせて見る。

校舎名は、不足人数マスタが「名古屋」、応募データが「名古屋駅前校」のように略されることがある。
店舗マスタの1校だけに前方一致する略称は同じ校舎として扱う。2校に当たるもの（「新宿」と「新宿本」）は別のままにする。

## 2. 上段のカード

| 数字 | 計算 |
| --- | --- |
| 直近週の応募 | 集計基準日を含む週（月〜日）に応募受付された件数。集計基準日は、取り込んだデータの最終更新時刻 |
| 前週差 | 直近週 − その前の週（確定済みの週） |
| 4週平均の応募 | 確定した直近4週の平均。集計途中の週は入れない（4日ぶんしかない週を1週として平均すると実態より低く出るため） |
| 選考中プール | いま「未対応・面接調整中・面接待ち・面接結果待ち」のいずれかにいる人数 |
| 面接待ち | 選考ステータスが「面接待ち」（面接日が確定済み）の人数 |
| **採用** | **この期間に採用が決まった人数**（ステータスが「採用」で、その更新日が期間内） |

## 3. 週次の応募数と採用数

- **青（応募）** … 応募受付日の週で数える
- **緑（採用）** … 採用が決まった週で数える。応募がいつかは問わない

同じ週の青と緑は別の人なので、対応しない。
緑の合計は、上の「採用」タイル、月次目標の「採用済み」と必ず同じ数字になる。

---

## 4. 選考ステータスの内訳・通過ファネル

**この期間に応募した人を追いかけた数**（コホート）。「どこで落ちているか」を見るためのもの。

ここに出る「採用」は、**その応募の中から採れた数**であって、上の「採用」タイルとは数え方が違う。
例：9月に応募した64件のうち採用3件（ファネル）／9月中に決まった採用18名（タイル）。
どちらも正しく、見ているものが違う。

## 5. 月次の目標と進捗

### 目標の作り方

1. **採用目標** = 不足人数マスタで**不足のあるコース1つにつき1名**（全校で61名）
   - 1人に2コース持たせて採用する場合も、コースごとに1名として数える（2026-10-14 指示）。
   - **10/13まではここが58名だった**（シートの「最小採用人数（全分野充足）」、空欄の校舎は不足枠の合計で代用）。
     銀座 1→3、天王寺 2→3 の2校だけが変わって61名になった。
   - シートに書かれている最小採用人数の単純合計は54名（記入のない校舎があるため、58名とは別の数）。
   - コース別の不足がどこにも書かれていない校舎だけ、シートの最小採用人数をそのまま使う。
2. **採用済み** = その期間に採用が決まった人数（校舎ごと）
3. **充足** = min(採用済み, 採用目標)。**残り** = 採用目標 − 充足
   - 人数だけの計算なので、**ITを2名採った校舎はCADが空でも「3 / 3」になる**。
     数字は人数のまま、色とコース名（オレンジ）で「コースは埋まっていない」ことを出している。
     残り人数・必要応募もコース単位で数え直すかは未決（カズヒコさんの判断待ち）。
   - 目標3名の校舎に4名採れたら「4 / 3名（133%） 残り0名」。
   - 超過したぶんは他の校舎の不足を埋めないので、残りからは引かない。
   - そのため合計では「目標 − 採用済み」が残りと一致しないことがある。合計行に理由を出している。
4. **月ごとの採用目標** = 残りを按分期間（既定は当月〜マスタで一番遅い期限）に1名ずつ配る
5. **必要応募** = 残り ÷（応募→面接率 × 面接→採用率）を**校舎ごとに1回だけ切り上げ**
   - 既定は 30% × 60% なので、1名採るのに応募5.6件。
   - 校舎ごとに切り上げるので、単純な「残り × 5.6」より少し多くなる。
6. **月ごとの目標応募・目標面接** = 校舎の必要応募・必要面接を、採用目標を置いた月へ配る（月の合計は必ず校舎の数に戻る）

### 足し算の関係（ここが合っていれば整合している）

| 式 | 例 |
| --- | --- |
| 採用目標 ＝ 充足 ＋ 残り | 61 ＝ 27 ＋ 34 |
| 月ごとの採用目標の合計 ＝ **按分開始より前に充足した人数を引いた残り** | 61 − 14 ＝ 47 |
| 採用済み ＝ 充足 ＋ 目標超過 | 32 ＝ 27 ＋ 5 |
| 月ごとの採用実績（+Nを含む）の合計 ＝ 採用済み | 17（9月）＋ 15（10月）＝ 32 |
| 月ごとの採用実績（+Nを除く）の合計 ＝ 充足 | 14 ＋ 13 ＝ 27 |
| 月ごとの目標応募の合計 ＝ 必要応募 | 90 ＋ 66 ＋ 25 ＝ 181 |

**月ごとの採用目標を足しても採用目標（61名）にはならない。**
配っているのは「按分期間が始まる時点で残っていた人数」だけで、それより前に充足したぶんは配らない。
按分期間より前の月（9月など）は実績だけを出していて、目標は持たない。

**月ごとの目標は、期間が始まった時点で決めたまま動かさない。**
期間中に採れたぶんで目標を減らすと、その採用が「残りを減らす」と「その月の目標を埋める」の
両方に効いてしまい、10月に15名採れたのに10月の目標も15名のまま（＝達成扱い）になる。
いまの残り（61 − 充足）は上の合計行に出す。月の目標の合計といまの残りの差は、期間中に充足したぶん。

### 月ごとの目標が、月をまたぐと変わる場合がある

「按分する期間」を選ばずに既定のままにしていると、**開始月が当月に追随する**。
その結果、前の月に採りきれなかったぶんが、残りの月に上乗せされる（ローリング）。

| いつ見たか | 按分期間 | 10月 | 11月 | 12月 |
| --- | --- | --- | --- | --- |
| 10月 | 10〜12月 | 20 | 14 | 10 |
| 11月 | 11〜12月 | − | 30 | 13 |
| 12月 | 12月のみ | − | − | 43 |

**経営会議に出す計画を固定したいときは、「按分する期間」で 10月〜12月 を明示的に選ぶ。**
選んだ期間はブラウザに記憶され、月が変わっても割り直されない。
その場合、10月の目標20に対して実績が足りなければ、11月・12月の目標は増えずに「未達」として残る。

### 実績の数え方

**月ごとの面接・採用は、採用管理表の「面接日」「（採用日）」で数える**（2026-11-05 修正）。

それまではジョブオプの**選考ステータス最終更新日**で代用していた。ジョブオプのエクスポートには
面接日がほとんど入っていない（実データ505件中5件）ため。最終更新日は後ろにしか動かないので、
前の月に面接・採用した人が直近の月に寄ってしまい、**8月の面接20件・採用12名が画面では0件**に
なっていた。採用管理表が未取り込みのときだけ、これまでどおり最終更新日で代用する（画面に明記）。

| 数字 | 出どころ | 日付 |
| --- | --- | --- |
| 応募 | ジョブオプ | 応募日 |
| 面接 | 採用管理表 | 面接日（R列） |
| 採用 | 採用管理表 | 採用日（Z列）。無ければ月に入らない |

応募と面接・採用で数えている日が違うので、**歩留まりは目安**。前の月に応募した人の面接が
その月に入るため、100%を超えることもある。


| 行 | 実績 |
| --- | --- |
| 応募 | その月に応募受付された件数 |
| 面接 | その月に面接段階へ進んだ人数（ステータス最終更新日の月） |
| 採用 | その月に採用が決まった人数のうち、**充足に効いたぶん**（ステータス最終更新日の月） |

**採用の実績は「充足に効いた人数」で出す。**
目標3名の校舎で5名採れた場合、充足は3名で止まり、はみ出た2名は他の校舎の不足を埋めない。
これを月の進捗に乗せると「10月 15/20」のように、充足していないぶんで達成に見えてしまう。
はみ出たぶんは消さずに、実績の横へ `+2` と出す（進捗バーには含めない）。

採用が「充足に効いたぶん」かどうかは、校舎ごとに決まった順で判定する。
先に決まった人から目標の人数までが充足に効き、それ以降は超過になる。

9月など按分期間より前の月は「実績」列として、目標なしで実績だけ出す。

### 表に出ない応募

不足人数マスタに採用目標が無い校舎の応募は、表にも合計にも入らない。
何件あるか・どの校舎かを表の下に出している。マスタに載っているはずの校舎がそこに出ていたら、名前の書き方がマスタと違う。

## 5.5 採用のゴール — 委託講師配置表「一般充足」（2026-11-05〜）

**採用の達成条件は、委託講師配置表「一般充足」シートの不足数が全校舎0になること。**

コースだけ合っていても埋まらない。平日夜しか入れない人を3人採っても土日のコマは空いたままなので、
**校舎 × 分野 × 時間帯**で見る。

| 項目 | 中身 |
| --- | --- |
| 読むシート | 「一般充足」。同じ形のシート（完全充足など）があっても、見出しの形（校舎名 ＋ IT【平日】）で選んだうえで「一般充足」を優先する |
| 分野 | IT / WEB / CAD の3つ。採用管理表の分野は WEBDTP・DTP・デザインを WEB に寄せる。**Office・英語などは配置表に枠が無い**ので、人数だけ別に出す |
| 時間帯 | 平日昼 / 平日夜 / 土日（配置表の【平日】【夜】【土日】、採用管理表の W〜Y列） |
| 不足コマ | シートの 校舎 × 分野 × 時間帯 の値をそのまま読む |
| 合計 | 不足コマの合計（シートの「合計」列） |
| 一般充足判定 | シートの式は `合計 ≤ 3 なら「充足」`。手で上書きされている校舎もあるので、**値をそのまま読む** |
| 不足数 | これから採る人数（**コマ数ではない**）。シートの式は `合計≤3 なら0、そうでなければ 分野ごとに（夜と土日の両方が足りるなら 平日+1、そうでなければ 平日+夜+土日）`。1人が約3日シフトに入れる前提。**こちらで計算し直さない** |
| 採用 | 採用管理表でステータスが「合格」の人を、W〜Y列の記入どおりにコマへ数える。1人が複数の時間帯に入れる場合は全部に数える |
| 時間帯の記入が無い合格者 | どのコマが埋まるか決められないので、推測で割り振らず人数だけ出す |

**コース × 時間帯の採用数**は、配置表が無くても出す別の表にしている。
充足の表は配置表（＝不足）を起点にしているので、配置表に載っていない校舎（六本木オフィスなど）や
枠の無いコース（Office・事務）の採用がそこには出てこないため。
マスは**その枠に入れる人数**で、1人が複数の時間帯に入れるなら全部に数える
（マスを足しても人数には戻らない）。時間帯の記入が無い採用はマスに入れず、人数にだけ入れる。

**配置表の最下行の合計とは一致しないことがある。** 画面の「不足数」は配置表に出ている校舎を
全部足した数だが、シートの最下行は式が `=R11+R16+R20+R21+R24` のように一部の校舎だけを
足していることがある（2026-11-12 時点で 豊田・福岡天神・大宮・船橋駅前・立川 の5校だけで21、
全校舎を足すと46）。校舎ごとの数はシートのとおりなので、合わないときは最下行の式を見る。

**「残りコマ」と「不足数」は単位が違う。** 残りコマはコマ数（不足コマ − 採用で埋まったコマ）、
不足数は人数。同じ数にはならない。

**引き算の前提。** 配置表の不足は「いま入っている講師を引いたあとの数」として扱い、
採用した人がまだ配置表に反映されていない前提で「残り」を出している。
反映済みの人がいると二重に引くので、ここは運用に合わせて直す必要がある（未確認）。

## 6. 校舎 × コースの応募と採用（採用チームの採用管理表）

ジョブオプのエクスポートに**分野（コース）が無い**ため、校舎ごとの人数までしか出せない。
採用チームが作っている採用管理表には分野が入っているので、**校舎 × コース**はこちらから作る。

**置き換えない。** 採用チームが手で付けている表なので、ジョブオプ側と数が合わないことがある。
どちらが正しいかはこの画面では決められないので、両方を並べて差を出す。

| 項目 | 中身 |
| --- | --- |
| 読む場所 | 「元データ」シート（無ければ先頭シート） |
| 読む列 | スクール / 分野 / ステータス / 応募日時 の4列だけ |
| 読まない列 | 氏名・年齢・性別・評価コメントなど。取り込みはブラウザの中で終わり、外には出ない |
| 採用とみなす | **「面接結果2」列か「ステータス」列のどちらかに採用と書いてあれば採用**（2026-11-05 修正）。どちらに書くかが運用で揺れているため。ただし**面接結果2が「辞退」「不採用」「不合格」なら採用にしない**（合格のあとで辞退した人がステータス側に残るため）。ステータス側で採用とみなすのは「合格」「採用」。以前はステータス列だけを見ていて、実ファイル392行で 79名 対 100名、CADが5名と7名で食い違っていた |
| 採用日 | 「（採用日）」列。「10/15」のように年が省かれているときは応募日の年を使い、応募日より前になる場合だけ翌年にする |
| 期間・対象校舎 | 画面の絞り込みと同じ（既定は 2026/07/23〜、不足人数マスタの校舎だけ）。外した行数は表の上に出す |
| 校舎名 | 「福岡天神」と「福岡天神校」のような表記ゆれは1行にまとめ、店舗マスタの略称にそろえる |
| コース | **IT / Webデザイン / CAD / Office / 事務 / カウンセラー / その他・未記入**。CAD、IT（Pythonを含む）、Office、事務 をそれぞれ別に拾い、**残り（WEBDTP・WEB・DTP・映像など）は Webデザイン**（2026-10-14 確認）。**分野が空欄の行だけが その他・未記入**。前の3つだけが不足人数マスタの `IT` / `D/W` / `C` と同じ区分で、Office・事務・カウンセラーには目標が無い（応募数と採用数だけ出す）。何が入ったかは表の下に出す |
| 並び替え | 表の見出しを押すと、その列で 降順 → 昇順 → 既定 と切り替わる |
| 目標（分母） | 不足人数管理表から、**不足のあるコースに1名**（朝昼・夜・土日のどれかに不足があれば1名）。校舎の合計もその積み上げ。枠の数をそのまま分母にすると「IT 15 / 50」となり、1人が朝昼も夜も持つ実態と合わないため。**コース不明には目標を置かない** |

**目標は61名。**コース別も校舎の合計も「不足のあるコースに1名」で数えるので一致する。
**1人に2コース持たせて採用する場合も、コースごとに1名として数える**（2026-10-14 指示）。
シートの「最小採用人数（全分野充足）」は銀座1名・天王寺2名のように2コース分を1名に寄せていて、
単純合計は54名（記入のない校舎あり）。画面にはこの合計も注記として出している。

**差が出る主な理由**

- 判断を入れたタイミングのずれ（Excelが先、ジョブオプが後、またはその逆）
- どちらか片方にしか入力が無い
- 校舎名の書き方の違い

### 応募と採用を1つの表にしている（2026-10-14）

見たいのは「このコースは何名ほしくて、何名採れて、応募は来ているか」なので、
コースごとに **応募 / 採用** の2列を並べ、1行で読めるようにしている。

**出どころが違う。** 応募はジョブオプ、採用はExcel、目標は不足人数管理表。

| 列 | 出どころ | 期間 |
| --- | --- | --- |
| 応募 | ジョブオプ。コースは求人の職種名から判定（§7） | コース分け後の求人からの応募だけコース別に数えられる |
| 採用 | 採用チームのExcel。分野の列がある | 全期間 |
| 目標 | 不足人数管理表 | — |
| コース不明 | 応募＝「その他」（コースを分ける前の求人・講師以外の求人）と、枠の無いコース（事務）／採用＝分野が未記入の採用 | — |

このため、**コースを分ける前に応募した人が採用されているコースは「応募より採用が多い」ことがある**。
誤りではないので、表の下に書いてある。合計の列では応募も採用も全期間なので食い違わない。

並びの既定は**埋まっていない枠が多く、応募も来ていない校舎**から。
不足人数管理表に載っているだけで応募も採用もまだ無い校舎も行として出す（いちばん困っている校舎なので）。

取り込みは右上の「その他」→「採用管理表（Excel）を取り込む」。
「公開データを更新」を押すと、この集計も先方の画面に出る。

## 7.5 週ごとの面接と内定（2026-11-12〜）

場所は「内訳」の先頭。採用管理表の**面接日**で週に分け、その面接がどうなったかを数える。
応募が増えても面接に進まなければ採用は増えないし、面接しても通らなければ同じなので、
どこで止まっているかを週で見るための表。

| 数字 | 中身 |
| --- | --- |
| 面接 | 面接日（R列）がその週に入っている人数。面接日が空の行は数えない（まだ面接していない・未記入） |
| 内定 | 画面の他の場所の「採用」と同じ判定（面接結果2＝採用、またはステータス＝合格・採用。面接結果2が辞退・不採用・不合格なら打ち消し） |
| 見送り | 不採用・不合格 |
| 辞退 | 辞退 |
| 検討中・不明 | まだ結果が書かれていない。「採用候補」「相談」もここ（**まだ決まっていない**ため） |
| 合格率 | 内定 ÷（内定＋見送り）。辞退と検討中は分母に入れない |

**結果が書かれる列が3つある。** 確かな順に 面接結果2（AA列）→ ステータス（I列）→ 面接結果（V列）。
面接結果2 は最後に入るので、そこだけ見ると直近の週が全部「検討中」になる。
面接結果（V列）は手書きの所見で「不採用＞採用」のような書き換えが入るので、矢印があれば右（最後に書かれたほう）を採る。

**面接結果（V列）の文字は保存しない。** 「採用（◯◯さん確認）」のように社内の人の名前が書かれていることがあり、
この画面はURLを知っていれば開けるため、取り込むときに判定（内定／見送り／辞退／検討中）だけに変えて持つ。

合格率の分母に辞退と検討中を入れていないのは、入れると**まだ結果が出ていない週の合格率が実態より低く見える**ため。
面接数を分母にした率は、各行の合格率にカーソルを置くと出る。

## 7.6 有料掲載のハイライト（2026-11-12〜）

掲載ステータス（校舎 × コースの有料 / 無料）を取り込むと、
**校舎 × コースの応募と採用**（§6）のマスに色が付く。

- **青** … 有料で掲載中で、応募も来ている
- **赤** … 有料なのに応募0 ← 求人の内容・条件・掲載エリアを見直す対象
- 無料掲載と掲載なしには色を付けない（色が付いているマスが、お金の出ている枠）

同じ「応募0」でも、無料なら当たり前、有料なら求人そのものを疑う話になるので、表の上で区別が付くようにしている。
表の上に「有料掲載 N枠／そのうち応募0が M枠」と、その校舎・コースの一覧を出す。

列の見出しからコースを判定する（IT / Python → IT、Webデザイン・DTP・映像 → Webデザイン、CAD、
APスクール事務 → 事務、Office、オンラインカウンセラー → カウンセラー）。
**「業務委託／パソコンスクール講師」はコースを分ける前のまとめ求人なので「コース不明」に入れる**
（この求人からの応募も「コース不明」に入っているため、同じマスで対応する）。
コースに結び付けられなかった列は捨てずに、表の下に名前を出す。

同じコースに有料と無料の求人が両方あるときは**有料を優先**する（お金が出ている枠が隠れると意味が無いため）。
