# 人事チームのExcelを自動で読み込む

人事チームが更新しているExcel（SharePoint / OneDrive）を、ダッシュボードが**開くたびに直接読みに行く**設定。
取り込みの操作は要らない。Excel側が更新されていれば、次に開いた人の画面から新しい数字になる。

設定していなければ何も起きない（これまで通り、手で取り込む運用のまま）。

---

## 1. どちらの経路で読むか決める

### A. 共有リンクをそのまま読む（Microsoft側の登録作業なし）

SharePoint / OneDrive で **「リンクを知っている全員」** の共有リンクを作れるならこれが一番早い。
作ったリンクを環境変数に入れるだけ。

社内ポリシーで匿名リンクが禁止されている場合は、ログイン画面のHTMLが返ってくるので使えない（その旨をエラーに出す）。その場合はBへ。

### B. Microsoft Graph 経由（社内限定リンクのまま読む）

Entra ID（Azure AD）にアプリを登録して、アプリ単体でファイルを読む。
テナント管理者の同意が1回要る。

1. [Entra ID のアプリ登録](https://entra.microsoft.com) → 新規登録（名前は何でもよい。リダイレクトURIは不要）
2. 「APIのアクセス許可」→ Microsoft Graph →**アプリケーションの許可** → `Files.Read.All`
   （SharePointサイト上のファイルなら `Sites.Read.All` も）→ **管理者の同意を与える**
3. 「証明書とシークレット」→ クライアントシークレットを作成（値を控える）
4. 「概要」から **アプリケーション(クライアント)ID** と **ディレクトリ(テナント)ID** を控える

---

## 2. Vercel に環境変数を入れる

https://vercel.com/kazu0331s-projects/job-requirement-ai/settings/environment-variables

| 変数 | 必須 | 中身 |
| --- | --- | --- |
| `EXCEL_SOURCE_URL` | ○ | Excelの共有リンク（A・Bとも必要） |
| `EXCEL_SOURCE_KIND` | ○ | `plan`（不足人数マスタ）または `applications`（ジョブオプの応募エクスポート） |
| `MS_TENANT_ID` | Bのみ | ディレクトリ(テナント)ID |
| `MS_CLIENT_ID` | Bのみ | アプリケーション(クライアント)ID |
| `MS_CLIENT_SECRET` | Bのみ | クライアントシークレットの値 |

入れたら **Deployments から Redeploy**（環境変数は再デプロイで反映される）。

---

## 3. 動いているかの見方

ダッシュボード右上に出る。

- `人事チームのExcelから自動取得（ファイル名 / 更新 10/12）` … 読めている
- `Excel連携エラー：…` … 読めていない。文面に原因が出る
  - 「ログイン画面が返りました」→ 匿名リンクが作れていない。Bの設定に切り替える
  - 「ファイルに接続できませんでした」→ リンクが違う、またはファイルが移動・削除された
  - 「ファイルを開けませんでした（403）」→ Graphのアクセス許可に管理者同意が無い

「最新に更新」ボタンでその場で取り直せる。

---

## 4. 注意

- Excelの中身は、これまで手で取り込んでいたファイルと**同じ形**である必要がある。
  不足人数マスタなら「不足人数管理表」シートの16列、応募エクスポートならジョブオプのdataシート。
  列を増やす・並べ替えるのは問題ないが、見出しの名前を変えると読めなくなる。
- 不足人数マスタの**緊急（オレンジ塗り）はセルの色で判定している**。
  Excelのまま置いておけば色は保たれる。CSVに変換すると色が落ちる。
- 読み取りだけで、Excelに書き戻すことはしない。
