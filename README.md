# 採用ダッシュボード

採用まわりの社内ツールをまとめていくアプリです。現在2つの機能が入っています。

| 画面 | 内容 |
| --- | --- |
| `/dashboard` | **採用モニタリング** — ジョブオプの応募エクスポートを毎週取り込んで、週次の応募状況・選考ファネル・校舎ごとの充足状況を見る |
| `/` | **求人要件ヒアリングAI** — RAが人事担当者から募集要件を聞き出すための対話型ツール |

## 採用モニタリングの使い方

### 1. 毎週、応募データを投げ込む

ジョブオプ（採用管理）からダウンロードした応募エクスポート（`.xls` / `.xlsx` / `.csv`）を
「応募データを取り込む」から選ぶだけです。Shift_JIS のCSVもそのまま読めます。

取り込むたびに**その時点の断面が「スナップショット」として履歴に積み上がります**。
ジョブオプのエクスポートは管理画面に出ている応募しか含まないので、
週次で積み上げることで、一覧から落ちた応募も履歴として残り、
「先週から誰がどこまで進んだか」まで追えるようになります。

### 2. 見られるもの

- **KPIタイル** — 直近週の応募数（前週差つき）、4週平均、選考中プール、面接待ち、採用
- **週次の応募数** — 応募受付日ベースの推移。棒にカーソルを合わせるとその週の内訳が出ます
- **いまのプール** — 選考ステータス別に、いま何人がどこに溜まっているか
- **通過ファネル** — 応募 → 面接設定 → 面接実施 → 採用 の転換率
- **軸ごとの週次推移** — 校舎 / 雇用形態 / 媒体 / 応募経路 / 職種 で切り替えられるクロス集計
- **不足人数に対する充足状況** — 採用計画と応募実績の突合（後述）
- **前回取り込み以降に動いた選考** — スナップショット間のステータス変化
- **不採用・辞退の理由**

雇用形態のフィルタがあるので、**正社員の募集を始めたら同じ画面で切り替えて見られます**。

### 緊急度の高い校舎

不足人数マスタで**校舎名のセルに色を付けてある校舎**を「緊急」として扱い、
画面の一番上に一覧で出します。そのうち選考中が0人の校舎は別に数えて赤で示します。
充足状況の表でも緊急の校舎を先頭に並べ、⚠緊急のラベルと左の色帯を付けます。

色の判定は「白以外の塗りつぶしがあるか」だけを見ているので、
塗り色を変えても、対象校舎を増減しても、ファイルを取り込み直せば追随します。

### スマホ

スマホ幅では「サマリー / 校舎別 / 充足状況 / 動き」のタブで切り替えます
（画面が広いときはタブが消えて全部縦に並びます）。
横に長い表はカードに組み替え、クロス集計表だけは横スクロール＋校舎名の列を固定しています。

### 3. 不足人数マスタ（採用計画）を入れる

「不足人数マスタを取り込む」から、校舎ごとの不足人数の表を取り込むと、
「不足人数に対する充足状況」が出ます。想定している列構成は次のとおりです（0始まり）。

| 列 | 内容 |
| --- | --- |
| 0 | フェーズ区分（今期 / FY28上期 など） |
| 1 | 校舎名 |
| 2 | 講座区分（`IT` / `D/W` / `C`） |
| 3–5 | グループA（3列） |
| 6–8 | グループB（3列） |
| 9–11 | グループC＝不足人数（3列） |
| 12 | 校舎計の不足人数 |
| 13 | 充足期限 |
| 14 | フラグ |
| 15 | 備考 |

1校舎につき `IT` / `D/W` / `C` の3行1組で、校舎名・フェーズ・校舎計・期限は
先頭行（IT行）にだけ入っていれば大丈夫です（結合セルは取り込み時に前方補完します）。
グループの見出し（1〜2行目）はファイルから読み取るので、日本語の見出しはそのまま画面に出ます。

校舎名は「北千住」でも「北千住校」でも応募データ側と突き合わせます。
突合できなかった校舎は「応募データ未突合」と表示されます。

### 4. スプレッドシートで見る

「スプレッドシートに書き出す（.xlsx）」で、次の8シートのブックが落ちてきます。
そのままGoogleスプレッドシートにインポートできます。

`週次推移` / `校舎別×週` / `雇用形態別×週` / `媒体別×週` / `ファネル` / `応募明細` / `計画vs実績` / `採用計画`

CSVで書き出す場合もUTF-8 BOM付きなので、ExcelでもGoogleスプレッドシートでも文字化けしません。

## データの保存先

取り込んだデータは**このブラウザのIndexedDBの中だけ**に保存されます。サーバーには送られません。

そのままだと初めて開いた人の画面が空になるので、すでに受け取っている分を
`public/seed/initial.json` に同梱してあり、**保存領域が空のときだけ**自動で読み込みます。
一度でも取り込み・削除の操作をしたブラウザでは二度と入りません。

シードは `scripts/build-seed.mjs` で作り直せます。

```bash
node scripts/build-seed.mjs <応募エクスポート> <不足人数管理表>
```

氏名・連絡先・住所などはそもそもアプリが取り込んでおらず、
年齢・性別も集計に使っていないためシードには含めていません
（応募ID・日付・校舎・雇用形態・職種・媒体・経路・選考ステータスのみ）。

- 別の端末やメンバーと共有する / バックアップを取る → 「バックアップ（.json）」で書き出して渡す
- 受け取った側は「バックアップを復元」で読み込む

将来的に複数人で常時共有したくなったら、この保存層（`lib/recruiting/storage.ts`）を
サーバー側のDBに差し替える想定です。集計ロジックはUIから独立しているのでそのまま使えます。

## 構成

```
app/dashboard/page.tsx        ダッシュボード画面
components/dashboard/         チャート・テーブル・取り込みパネル
lib/recruiting/
  parse.ts                    ジョブオプのエクスポートを正規化
  status.ts                   選考ステータスマスタとファネル段階の定義
  merge.ts                    スナップショットの串刺しとステータス変遷
  week.ts                     週次バケット（月曜始まり）
  aggregate.ts                集計（週次推移・プール・ファネル・クロス集計）
  plan.ts                     採用計画（不足人数マスタ）の読み書き
  shops.ts                    校舎マスタ
  storage.ts                  IndexedDBへの保存
  export.ts                   CSV / xlsx 書き出し
types/recruiting.ts           ドメイン型
```

## 技術スタック

Next.js 16 / React 19 / TypeScript / Tailwind CSS / SheetJS

## セットアップ

```bash
npm install
npm run dev
```

ブラウザで [http://localhost:3000/dashboard](http://localhost:3000/dashboard) を開いてください。

## デプロイ

Vercelにインポートして、ビルドコマンド `npm run build`、フレームワークプリセット Next.js で動きます。
