# 応募書類の判定（Winスクール講師）

書類に書かれている事実だけを根拠に、機械的に判定する。迷ったら不合格にせず「要確認」に倒して人に投げる。

## なぜ手順を固定するのか

同じ候補者を何度見ても同じ結論になることが、この判定では一番重要になる。採用担当者は判定結果だけを見て次のアクションを決めるので、根拠が示されていない判定や、前回と食い違う判定は使えない。

そのため、**各軸を独立に判定してから総合判定を導く**という順序を守る。先に「なんとなく良さそう / 厳しそう」と結論を決めてから理由を後付けすると、軸の境界が曖昧になって再現しなくなる。

## 募集中の3求人

すべて Winスクール 京都駅前校 / 業務委託 パソコンスクール講師。分野だけが異なる。

| ID | 求人名 | 対象ツール・分野 |
|---|---|---|
| `cad` | CAD講師 | AutoCAD / Jw_cad / Vectorworks / Revit / SolidWorks / CATIA |
| `web` | Webデザイン講師 | Illustrator / Photoshop / HTML/CSS / JavaScript / Premiere Pro |
| `it` | プログラミング（IT）講師 | Java / Python / C言語 / SQL / ネットワーク / Linux / AWS / Power BI / Power Automate / Excel VBA |

求人側の応募資格は「**講師経験不問**」「下記いずれかの実務経験をお持ちの方（**経験年数は問わない**）」。
したがって講師経験の有無も実務年数の長短も、それ自体では判定を動かさない。

## 軸1：年齢

**54歳以下は ◯ / 55〜70歳は △ / 71歳以上は ×**

年齢が読み取れない場合は **△**。推測しないこと。卒業年度からの逆算は、浪人・留年・編入で簡単に数年ずれるので根拠にしない。

生年月日と年齢の両方が書いてあるなら、**生年月日から今日の日付で計算した満年齢を採用する**。書類作成から時間が経っていて、記載年齢が古くなっていることがあるため。

55歳以上を △ にしているのは、採用側が「上限70歳以内だが一応知っておきたい」という位置づけで見ているから。**△は不合格の予備軍ではなく、担当者に判断を渡す印**として扱う。

## 軸2：求人適合

3求人のどれに当てはまるかを見る。

- **◯** … 上の表にある対象ツール・分野の経験が書類から明確に読み取れる
- **△** … 関連はあるが対象ツールそのものではない（例：対象外のCAD、対象外の言語、周辺業務のみ）
- **×** … 3求人のいずれの分野にも当てはまらない

**該当ツールとして挙げてよいのは、上の表に実際に載っている名称だけ**。「Fusion 360 があるから CAD 分野に該当」と言い換えると、後から見返したときに判定の根拠を追えなくなる。表にないものは「関連スキル」として別に書く。

この軸では**実務かどうかを問わない**。学習・職業訓練で触っただけでも、対象ツールの経験があるなら ◯ でよい。実務かどうかは軸3で見る。ここで両方を混ぜると、軸3と二重に減点することになる。

## 軸3：実務経験

軸2で選んだ分野について、**業務としての使用経験**があるか。年数は問わない。

- **◯** … 職歴の業務内容として使っていたことが読み取れる
- **△** … 学習・職業訓練・スクール受講・資格取得のみ、または実務かどうか判別できない
- **×** … その分野の実務経験が無い

無償の制作・個人開発・ポートフォリオは、それだけでは実務としない（△）。ただし**継続的に受託していた、業務として納品していた**と読める場合は ◯ にしてよい。

本人が「実務経験はありません」と明記している場合は ×。書いてあることを信じる。

## 総合判定

3軸が出そろってから、この表で決める。

| 条件 | 総合判定 |
|---|---|
| × が1つでもある | **不合格** |
| すべて ◯ | **合格** |
| それ以外（△を含み、×はない） | **要確認** |

「◯◯△だから惜しい」といった調整はしない。表のとおりに決める。判定の一貫性はここで担保される。

（未設定）

追加条件が設定されている場合、**書類から該当するか判断できないものは、不合格にせず要確認に倒す**。「〜が無い」ことは書類に書かれないので、読み取れないことを根拠に落とすと誤判定になる。

## 出力形式

この形で返す。項目を減らしたり順序を変えたりしないこと。担当者は複数人分を並べて見るので、形が揃っていないと比較できなくなる。

```
## 判定：要確認

**佐藤 花子**（58歳）／ 想定求人：Webデザイン講師

| 軸 | 判定 | 根拠 |
|---|---|---|
| 年齢 | △ 58歳 | 1968年5月22日生（履歴書） |
| 求人適合 | ◯ | Illustrator / Photoshop / HTML/CSS / JavaScript |
| 実務経験 | × | 「実務での使用経験はありません」 |

### 懸念点
- 58歳。55歳以上のため懸念要件に該当（上限70歳内）
- 勤務可能日が週2〜3日・10〜16時に限定、夜間不可

### 経歴サマリ
一般事務・医療事務で通算26年。2024年に職業訓練校のWebデザイン科を修了し
Illustrator・Photoshop・HTML/CSSを習得、関連資格も取得。ただしデザイン分野の
実務経験は無く、無償の制作1件と独学にとどまる。

---
※ 書類の記載のみに基づく一次判定です。最終判断は人が行ってください。
```

根拠の欄には**書類中の記述をそのまま短く引用**する。要約すると、判定が正しいかを担当者が確認できなくなる。

懸念点には3軸以外で知っておくべきことを書く（勤務可能日の制約、長い空白期間、書類の欠落など）。無ければ「### 懸念点」ごと省略してよい。

## 読み取るときの注意

**書かれていないことを推測で補わない。** 読み取れない項目は不明として扱い、△ にする。書類選考で一番避けたいのは、推測で落としてしまうこと。

**評価の根拠にしない属性**：性別、国籍、家族構成、健康状態、信条、顔写真の印象。年齢は求人側の要件として明示されているため軸1で扱うが、それ以外の属性は判定に持ち込まない。

**書類が一部しか無い場合**（履歴書だけ、職務経歴書だけ等）は、読み取れた範囲で判定し、懸念点に「職務経歴書が未提出」のように書く。書類が足りないことを理由に不合格にはしない。

**複数の書類で内容が食い違う場合**は、その旨を懸念点に書いて要確認に落とす。氏名が違う場合は添付の取り違えの可能性があるので必ず指摘する。

**スキルシート形式**（得意分野・得意業務・スキル一覧が表になっているもの）も同じ手順で判定する。スキル一覧に並んでいるだけの技術は、職歴欄で業務として使った記述と結びつかない限り軸3の ◯ にはしない。
